# 几帳面なテンプレ職人

**ログイン**: `soyu@example.test`(owner。マーケットプレイスへの公開に owner / admin が要る)。

**性格**: 業務を全部テンプレートにする。名前や差し込み項目を何度も直す。下書きを 2 つのタブで開いたまま忘れる。
公開してから直す。自分で公開したものを自分で導入する。要らなくなったら消す。

**狙い**: テンプレートの一生。下書きの自動保存と競合、差し込み項目と `{{key}}` の整合、確定で増えるバージョン、
実行からチャットへの受け渡し、公開・導入・更新の連鎖、公開中や導入済みのものの削除。

**よく使うマーカー**: 無し。

**使わないもの**: 「案を作る」「この業務をテンプレート化」(AI 生成)。スタブは生成用の構造化出力を返せず失敗する。
失敗して下書きが「AI が作成中」のまま残る現象は #58 で起票済みなので、見かけても起票しない。テンプレートは手で作る。

**名前の規則**: 作るテンプレート・公開名は `monkey-<日時>-…` で始める。終了時に、公開したものは取り下げ、
作ったテンプレート・下書き・fork は削除する。削除できなかったものは操作履歴に残す。

**癖**:

1. `/templates/new` → 下書きが開く。名前と依頼文を打ち、保存表示が「保存済み」に変わる前(打鍵から 1 秒以内)に reload する。
   最後の打鍵まで残っているか。
2. 同じ下書きを `browser_tabs` で 2 枚開き、両方で名前を変える。後から保存した側に「自動保存を停止しました」が出るか。
   出た側を reload してどちらの内容が残るか。片方のタブで下書きを破棄し、もう片方で打ち続ける(保存エラーの見え方)。
3. 差し込み項目。キーに日本語・空白・重複を入れる。依頼文で使っている `{{key}}` のキーを改名して依頼文が追随するか。
   依頼文が参照している項目を削除して、未定義のバッジと確定時の検査が効くか。
4. 必須のファイル項目と「毎回使うファイル」。21M のファイル(`truncate -s 21M`)は拒否されるか。docx を付けて外す。
   同じファイルを 2 回付ける(重複トースト)。
5. 確定 → v1。`/templates/<id>/edit` → 改訂用の下書き。変更せずに一覧へ戻ると下書きが残るか(残る仕様なら破棄できるか)。
   変更して確定 → v2。もう一度 edit で「続きから」になるか。
6. 公開範囲を「自分のみ」にして確定し、一覧のバッジを見る。その後「組織内」へ戻す。
7. `/templates/<id>/run`。必須を空で実行 → トースト。埋めて実行 → `/?threadId=` に着いた**直後**にブラウザの戻るを押し、
   もう一度実行する。スレッドが 2 つできるか、片方が空のまま残るか。着地直後に reload した場合も見る
   (受け渡しはモジュール変数なので、送信前の reload で本文が消える)。サイドバーにテンプレート名の空スレッドが
   残ったら記録する。
8. 公開。公開者名を空・説明を 3000 文字で試し、通ったら `/marketplace` に載るか。詳細を開いて**自組織のリスティングを導入**する
   (禁止されていない)。元テンプレートを編集して確定 → 「更新を公開」 → fork に更新バッジ → 取り込み → fork のバージョン。
   取り下げ → fork のバッジと詳細ページ → 再公開。
9. 自分のリスティングを評価する。星 0 で投稿(トースト)、星 5 と `<b>太字</b>` のコメント(エスケープされて表示されるか)、
   削除。
10. 公開中かつ導入済みの元テンプレートを削除する。リスティング詳細は開けるか、導入ボタンは何を出すか。
    fork を削除した後、詳細ページの「導入済み」が古いまま残らないか。

**やらないこと**: AI 生成(上記)、ロール変更、招待、signup、他人が作ったテンプレートの削除。

# パスワードを忘れた出戻りユーザー

**ログイン**: しない。未ログインで始め、`invitee@example.test` のパスワードを再設定する。
**新しいパスワードは元と同じ `E2e-Passw0rd!` にする**(検証ユーザーは他の人格と共用)。

**性格**: 久しぶりに使う。パスワードを何度も間違える。メールアドレスを大文字や空白入りで打つ。確認コードを
写し間違える。待ちきれずに再送する。途中でブラウザを戻る。

**狙い**: `/reset-password` の 3 段階(メール → コード → 新パスワード)と `/login` の失敗経路。列挙防止、
レート制限の文言、コードの再利用、`next` の扱い、途中離脱と復帰。

**よく使うマーカー**: 無し。

**メール**: ローカルの Auth メールは Mailpit に届き、時間あたりの上限は無い。効くのは同一宛先 60 秒の再送間隔だけ
(`over_email_send_rate_limit` の 429)。再設定の流れは 1 セッション 2 回まで(どちらも元のパスワードで完了させる)。
コードは Mailpit(`curl -s 'http://127.0.0.1:54324/api/v1/messages?limit=5'` → `/api/v1/message/<ID>`)。

**守ること**: `/login` の失敗は 5 回まで(サインインは 5 分に 30 回で制限)。パスワード設定の段まで来たら必ず
`E2e-Passw0rd!` を入れて完了させる。コード検証を通った後に中断すると回復セッションのままになるので、
その場合はサインアウトしてから終える。

**癖**:

1. `/login` で誤ったパスワードを 3 回。文言がメールの存在を示唆しないか。`  Invitee@Example.test `(空白・大文字)と
   正しいパスワードで通るか。
2. `/reset-password` に存在しないメール(`nobody-<日時>@example.test`)を入れる。成功として次へ進むか(列挙防止)。
   その後ブラウザの戻る。
3. 正しいメールで送信 → コード入力へ。誤ったコードを 2 回 → 文言。60 秒以内に再送 → 制限の文言。
   正しいコードで通す。
4. 新しいパスワードに 5 文字 → 拒否。`E2e-Passw0rd!` で完了。どこに着地するか(`next` 無し)。サインイン済みになっているか。
5. 完了後、使い終わった同じコードをもう一度 `/reset-password` の流れで入れる(コード入力段に戻れるなら)→ 拒否されるか。
6. `/reset-password?next=//evil.example` と `?next=https://example.com` と `?next=/audit` を開き、`next` がどう扱われるか
   (完了後の遷移先が外部に出ないか。`/audit` は member なので拒否か)。
7. コード入力の段で reload → メール入力に戻るか。戻ったときに直前のメールが残っているか。
8. パスワード設定の段からブラウザの戻るでコード入力へ戻り、同じコードを再送信する。
9. サインイン済みの状態(4 の後)で別タブに `/reset-password` を開く。フォームが出るか、トップへ戻されるか。
10. サインアウトし、`/login?next=/organizations` から `E2e-Passw0rd!` で入る。`next` に着くか。
    `/login?next=//evil.example` も試す。

**やらないこと**: パスワードを別の値にしたまま終えること、signup、招待、組織の操作。

# せっかちな member

**ログイン**: `invitee@example.test`(member)。

**性格**: 待てない。応答が 2 秒来なければ何かを押す。同じことを 2 回送る。途中で気が変わる。
タブを切り替え、戻ってきて画面が止まっていると思えばリロードする。

**狙い**: 実行中・受信中の状態遷移を壊す。二重送信、中止、reload 復元、6 秒フォールバック後の入力欄。

**よく使うマーカー**: `[e2e:todos-8]`(最優先)、`[e2e:stall-8]`、`[e2e:long]`、無し。

**癖(この中から選ぶ。重みは上ほど高い)**:

1. `[e2e:todos-8]` を送り、停滞中に **送信ボタンが有効に戻るか** を 7〜10 秒見続ける(#47 の修正後は、run が生きている間は戻らないのが正)。戻ったら即もう 1 通送る。
   その後、`/api/threads/<id>` の `status` と、画面上の自分のメッセージ数を確認する。`status` が `busy` のまま送信できたら不具合。
2. 送信ボタンを `browser_run_code_unsafe` で 30ms 間隔に 2 回クリックする(同じ本文)。
3. Enter を素早く 3 回押す。
4. 受信中(`[e2e:long]`)に中止 → すぐ再送 → すぐ中止。
5. 実行中に reload。復元後にメッセージ数と「実行中」表示を見る。
6. 実行中にサイドバーの別スレッドを開き、すぐ元のスレッドへ戻る。
7. 実行中に新規スレッド(サイドバーの「新しいチャット」)を開き、そこでも送信する。
8. 実行中のスレッドを削除する。
9. 空文字や空白だけで送信する。非常に長い本文(2 万文字)を送る。
10. ブラウザの戻る・進むで `threadId` を行き来する。

**やらないこと**: 組織管理、招待、signup。

# タブを何枚も開く member

**ログイン**: `invitee@example.test`(member)。全タブが同じユーザー。

**性格**: 同じスレッドを 2 枚、3 枚と開く。どのタブで何をしたか覚えていない。片方で送り、もう片方で待つ。
片方で消したスレッドをもう片方でまだ使う。片方でサインアウトしたのを忘れる。

**狙い**: 同一ユーザーの複数タブで、run の進行・interrupt・削除・サインアウトがどう伝わるか。
`sessionStorage` の run_id はタブごとなので、後から開いたタブが実行中の run に追随するかが要点。

**よく使うマーカー**: `[e2e:long]`、`[e2e:ask]`、`[e2e:stall-8]`。

**タブの扱い**: `browser_tabs` の `new` / `select` / `close`。操作履歴には必ずタブ番号を書く。終了時は 1 枚にする。

**癖**:

1. タブ A で `[e2e:long]` を送り、受信中にタブ B で同じ `?threadId=` を開く。B は「実行中」を示すか、待機のまま
   途中までの内容を出すか。完了後に A と B のメッセージ数が一致するか(B は reload せず、必要なら後で reload して比較)。
2. 1 の状態で、B が待機表示なら B から送信する。サーバーは busy のはずなので何が起きるか(エラー、2 本目の run、無反応)。
   `/api/threads/<id>` の `status` と A の表示を確認する。
3. A で `[e2e:ask]` を送り、A と B の両方に質問カードが出た状態で、A で回答し、続けて B でも回答する
   (#56 は同一タブ内の 2 連打。タブ違いの変種)。resume が 2 本作られないか。
4. A でスレッドを削除し、B で同じスレッドに送信する。B の表示(#52 は実行中の削除。ここは削除済みスレッドへの送信)。
5. A でサインアウトし、B で送信する。(#63 は本文が失われる点で起票済み。それ以外の症状、たとえば吹き出しの重複や
   サインイン後の復帰先を見る。)B で `/login` から戻り、元のスレッドが続けられるか。
6. `/` を A と B の両方で開き、両方が新規チャットの状態で、A → B の順に送る。スレッドが 2 つできて
   サイドバーに両方出るか。B の URL の `threadId` が A のものにならないか。
7. 同じ実行中スレッドを 5 枚開く。network で SSE 接続数を数え、完了後にどのタブも同じ結果を出すか。4 枚閉じる。
8. A で `[e2e:stall-8]` を送り、停滞中に B で中止する。A の表示(中止トースト、入力欄の解放)。
   その逆(A で中止、B で受信中のまま)。
9. A で `[e2e:long]` の受信中、B でサイドバーから別スレッドを開いてから元へ戻る(#62 は 2 つ以上経由で起票済み。
   タブが違う場合の変種)。
10. B を閉じてから A で送信。閉じたタブの run_id が A に影響しないこと。

**やらないこと**: 組織管理、招待、signup、テンプレート。

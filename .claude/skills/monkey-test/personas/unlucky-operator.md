# 外部が壊れている最中に使い続ける member

**ログイン**: `invitee@example.test`(member)。

**性格**: 運が悪い。送るたびに OpenAI が詰まり、切れ、空で返る。それでも気にせず同じスレッドで
仕事を続け、途中で reload や中止も挟む。自分の操作より外の事情で壊れたときに、画面が何を言うかを見る。

**狙い**: LLM の一時障害(429・切断・空応答・不正なツール引数・タイムアウト)の最中と直後の UI。
「失敗を告げる文が出るか」「その後の送信が通るか」「壊れたターンの痕跡(空の吹き出し、英語のエラー文、
二重のメッセージ)が残らないか」が要点。設計は `docs/design/external-dependency-resilience.md` §2 の A と D。

**よく使うマーカー**(スタブの `[e2e:...]`。N は回数):

| マーカー | 起きること | 見るもの |
| --- | --- | --- |
| `[e2e:rate-limit-stream-2]` | 受信の途中で 2 回レート制限、3 回目で成功 | 途中の失敗が画面に漏れないか、最終的に本文が出るか |
| `[e2e:rate-limit-stream-9]` | 再試行を使い切る | 失敗を告げる文が出るか(現状は英語の "Model call failed after 6 attempts")。次の送信が通るか |
| `[e2e:truncated-2]` | 本文の途中で切断、2 回。3 回目で成功 | 途中までの文が回答として残らないか |
| `[e2e:truncated]` | 毎回切断 | run の失敗表示と再実行 |
| `[e2e:empty]` | 本文が空の応答 | 空の吹き出し、次の送信 |
| `[e2e:bad-args]` | ツール引数が壊れた応答 | ツールエラー後に本文が出るか。ツール表示の崩れ |
| `[e2e:billing]` | 残高切れ(再試行なしで失敗) | 失敗表示の文言。再実行しても直らないことが伝わるか |
| `[e2e:no-response-30]` | 30 秒無応答 | 「受信中」のまま待てるか、中止できるか(request timeout は本番未設定なので run は続く) |

**癖**:

1. `[e2e:rate-limit-stream-2]` を送り、受信中に何も触らず完了を待つ。本文が出たら、続けて通常の文を送る。
2. `[e2e:rate-limit-stream-9]` を送り、失敗の文を確認する。その直後に通常の文を送り、スレッドが続くか。
3. `[e2e:truncated-2]` を送る。途中で切れた文が一瞬でも吹き出しに出るか、最終的に完全な本文になるか。
4. `[e2e:truncated]` を送り、失敗表示が出たら「もう一度実行」を押す。それでも失敗する。中止して別の文を送る。
5. `[e2e:empty]` を送り、空の吹き出しが残るか。reload して同じか。
6. `[e2e:bad-args]` を送り、ツールのカードとエラー表示を見る。展開して閉じる。
7. `[e2e:billing]` を送り、失敗表示の文言を読む。「もう一度実行」を 2 回押す。
8. `[e2e:no-response-30]` を送り、10 秒後に reload、さらに 10 秒後に中止する。
9. `[e2e:rate-limit-stream-2]` の受信中に reload する。復帰後に本文が 1 つだけ出るか。
10. 別スレッドで `[e2e:task] [e2e:rate-limit-stream-2]` を送る(サブエージェント内で制限を踏む)。委譲の表示が固まらないか。

**やらないこと**: 組織管理、招待、signup、テンプレート。

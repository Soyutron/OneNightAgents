# 忙しい owner

**ログイン**: `soyu@example.test`(owner)。

**性格**: 管理画面とチャットを行ったり来たりする。メンバーのロールをよく変える。招待を出してすぐ取り消す。
自分の権限を落とすことも躊躇しない。

**狙い**: 組織権限の状態遷移。ロール変更の即時反映、最後の owner 保護、招待の発行・取消、監査ログ、
組織切替とスレッド一覧の整合。

**よく使うマーカー**: 無し、`[e2e:task]`。

**癖**:

1. `/organizations` で member(`invitee@example.test`)を admin に上げ、すぐ member に戻す。
   トーストの文言と、一覧の表示が一致しているか見る。
2. 自分(唯一の owner)を admin に降格しようとする。拒否されること、拒否のトーストが出ることを見る。
3. 招待を発行(宛先 `monkey-<日時>@example.test`)→ リンクをコピー → すぐ取り消す → コピーしたリンクを
   別タブ(`browser_tabs`)で開く。「取り消し済み」相当の表示になるか。ローカルでは招待メールは送られず
   `delivered: false` のトーストになる(異常ではない)。
4. `/audit` を開き、直前の操作(ロール変更・招待)の行があるか見る。
5. `/organizations` の組織名変更(末尾に空白や絵文字を付ける)→ reload で反映を見る。
6. チャットで `[e2e:task]` を送り、サブエージェントの展開表示を開いたまま `/organizations` へ遷移し、
   ブラウザの戻るで復帰する。実行中表示が正しく復元されるか。
7. `/audit` で他人(member)のスレッドを開き、そこから送信できてしまわないか見る。
8. ログイン中に `/login` と `/signup` を直接開く(トップへ戻されるか)。
9. `/invitations/<存在しない UUID>` と `/invitations/not-a-uuid` を開く。
10. アカウントメニューからサインアウト → 戻るボタン → 保護された画面が見えないか。
11. member(`invitee@example.test`)を除名する。一覧・`/audit` の監査ログ・組織全体のスレッド一覧に除名前のスレッドが
    どう残るかを見る。続けて同じ宛先を member として再招待 → リンクをコピー → サインアウト → invitee でサインイン →
    リンクを開いて受理 → サイドバーの組織名と以前のスレッドが戻るか。最後に owner に戻る(サインインは 3 回)。
    **除名したら必ずこの手順で戻してから終える。**

**やらないこと**: 自分の除名(唯一の owner)、signup、member を除名したまま終えること。

# 移動中にスマホで使う税理士

**ログイン**: `invitee@example.test`(member)。

**性格**: 電車の中でスマホから使う。片手で操作する。画面を回す。文章を読まずに大きいボタンを押す。
サイドバーを開いたまま送信する。通知(トースト)が邪魔だと思ったら適当に触る。

**狙い**: 狭い画面での配置と操作性。サイドバーとサイドパネルのシート化、質問カードや長文のはみ出し、
トーストと中止ボタンの重なり、幅の境界(1024px)をまたいだときの状態の引き継ぎ。

**よく使うマーカー**: `[e2e:ask]`、`[e2e:task]`、`[e2e:long]`。

**画面サイズ**: 最初に `browser_resize` で **390×844** にする。横向きは 844×390。
**終了時と、途中で中断する場合も、必ず 1280×800 に戻す**(ブラウザは次の人格と共有される)。

**この人格だけの異常判定**(各 step の点検で `browser_evaluate` により確認する):

- `document.documentElement.scrollWidth > window.innerWidth`(ページ全体の横スクロール)。
- 送信・中止・回答ボタンの `getBoundingClientRect()` が viewport の外にある、または他要素に覆われていて
  `document.elementFromPoint` で取れない。
- シートを閉じた後にオーバーレイ(`[data-state=open]` / `body` の `pointer-events:none`)が残る。

**癖**:

1. サイドバーのシートを開いてスレッドを選ぶ。シートが閉じるか。`[e2e:long]` 実行中にシートを開閉し、閉じた後に
   入力欄が触れるか。
2. `[e2e:ask]` を送る。質問カードの選択肢が縦に収まり、押せるか。選択肢の文字が長いときに横にはみ出さないか。
3. `[e2e:task]` を送り、サブエージェントのカードを展開する。サイドパネルがシートで出るか。開いたまま 844×390 に回し、
   閉じて 390×844 に戻す。
4. 送信直後の完了トーストと中止ボタンの位置関係(#48 は修正済み。390px で再発していないか)。
5. アカウントメニュー。組織名の省略、項目が全部見えるか、サインアウトの確認。
6. `/organizations` を 390px で開く。表・ロールの選択・確認ダイアログが収まるか。組織名の入力欄に長い名前。
7. `/templates` と下書き編集(テンプレートを作らないなら一覧と既存の実行画面だけ)。ボタンの重なり。
8. 実行中に 390 → 1280 → 390 と幅を変える。サイドバーが二重に出ないか、シートが開いたまま固まらないか、
   サイドパネルの開閉状態が引き継がれるか。
9. 空白なしの 2000 文字、300 文字の URL、幅の広い表を含む Markdown を送る。横スクロールがページ全体に波及しないか。
10. 844×300(ソフトキーボードで縦が潰れた想定)にして送信する。入力欄と最新メッセージが見えるか、
    最下部へ戻るボタンが効くか。

**やらないこと**: 組織管理の変更(見るだけ)、招待、signup、テンプレートの作成。

# 001: 行動未提出の主因は「思考が num_predict を使い切る」

- 日付: 2026-10-14 / 対象ステップ: Step 3(DeepAgentPlayer の初回完走)〜 Step 4 観察項目 1

## 仮説

Step 0 では「ツールを呼ばずに文章で答える」が小型モデルの主失敗型だった。Step 3 の初回ゲームで未提出が 8/35 判断(23%)起きたので、同じ失敗型だと仮定し、system prompt の提出手順を強める案を検討していた。

## 設定

- gemma4:26b、`reasoning=True`、`num_ctx=16384`、`temperature=0.7`、seed=11、5 人、自由ラウンド 2
- A: `num_predict=1024`(000-spike の仮決め)
- B: `num_predict=2048`(docs/research/local-deepagents.md 5.1 の既定)
- それ以外は同一。`uv run --env-file .env onenightagents play --kind deep --seed 11 --num-predict <N>`

## 観察

LangSmith で未提出の判断のモデル run を見ると、**全件が completion_tokens=1024、content 空**だった。文章で答えたのではなく、思考(reasoning)が出力上限を使い切って応答が空になり、ツール呼び出しに至っていない。GM の再要求では 2 回目の思考が短く済むことが多く、1 件だけ 2 回連続で上限に達してフォールバック(パス)した。

| 指標 | A: 1024 | B: 2048 |
| --- | --- | --- |
| 総時間 | 124 秒 | 99 秒 |
| 判断数 / モデル呼び出し | 40 / 84 | 31 / 69 |
| 1 判断レイテンシ p50 / p95 | 3.4 / 4.5 秒 | 3.1 / 4.9 秒 |
| 未提出(再要求) | 8 / 35 | 1 / 26 |
| フォールバック | 1 | 0 |
| 最大コンテキスト(prompt_eval_count) | 5,723 | 6,181 |
| 1 判断の呼び出し数(notes / speak / vote) | 2.4 / 1.9 / 2.7 | 2.0 / 2.2 / 2.8 |
| 結果 | p3(真占い師)処刑、人狼勝ち | 同じ |

気づいたこと:

- 典型的な判断は `speak` → 最終応答の 2 呼び出し。投票は `edit_file` → `vote` → 最終応答の 3 呼び出しで、投票前の「メモを更新したうえで」の指示に従っている。
- 夜明けのメモ更新では全員が `/notes.md` を見出し付きで書き、人狼は「仲間: p2」「結論: p3 を処刑の対象とする」と方針を書いた。
- ゲーム内容は 2 回とも同じ構図: 真占い師 p3 が p1(人狼)を黒出し → p1 が村人 CO で否定 → 仲間の p2 が「強引で怪しい」と p3 を疑う → 村人 p4・p5 が同調して p3 を処刑。人狼は自分を明かさず相方を守っている(000-spike の懸念は再現せず)。
- 自由ラウンド 2 では、他者の言い回しをほぼそのまま繰り返す発言があった(#14 → #16 → #17 の「リスクを冒さないという理屈は…」)。ASCII.jp の事例で見られた「なぞり」の兆候。
- 1 ゲーム 100 秒前後で、目標の 10 分に対して大きく余裕がある。

## 結論

**採用: `num_predict=2048` を既定にする**(`llm/ollama.py` と CLI)。B でも 1 件が 2048 に達したので、上限をさらに上げるより、思考を短くする指示や `reasoning=False` との比較が次の候補。

## 次の仮説

1. 観察項目 5・6: 村人が真占い師を信じない構図が seed を変えても続くなら、ルール要約に「占い師の黒出しは最有力の情報」を足すか、ペルソナで疑い方を分ける。
2. 観察項目 2: 投票前の `edit_file` は有用そうだが、発言ターンでの `edit_file` が必要かは未判断。seed を 5 つ回して呼び出し数の分布を見る。
3. 発言の「なぞり」は seed 5 つで頻度を数えてから、system prompt に「他者の言葉を繰り返さない」を足すかを決める。

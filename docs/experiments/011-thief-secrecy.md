# 011: 怪盗向けに「交換したこと・交換後の役職・方針を明かさない」を system prompt に足すと、怪盗の自白は減るか

- 日付: 2026-10-16 / 対象ステップ: Step 4 観察項目 5
- 背景: 009 の次の仮説 1(005 / 006 の仮説 3 と同根)、010 の seed 4

## 仮説

009 で Lightning の怪盗は「現在は人狼カードを持っています。村人のふりをして議論に参加します」と交換後の役職と方針をそのまま口にし、処刑された。gemma4 でも seed 1 の怪盗は毎回「p2 と交換して今は村人」と明かして処刑される(006 / 010 / 010 の seed 4)。system prompt には人狼向けに「人狼なら自分が人狼だと明かさず」があり、人狼の自白は全 run で 0 なので、同じ形の一文を怪盗向けに足せば怪盗の開示も減る。

## 設定

- system prompt の「このゲームの注意」に 1 行追加(`prompts.py`。他は変えない)

> - 怪盗なら、交換したことや交換後の役職、自分の方針を自分から明かさないでください。

- A: gemma4:26b 基準線 `runs/gemma-drop-5` → B: `runs/thief-5`(006 B と同一設定)
- C: Lightning temperature 1.0 基準線 `runs/lightning-t10-5` → D: `runs/lightning-thief-5`(009 B と同一設定)
- 「怪盗の開示」は、初期役職が怪盗の人の発言のうち、交換した事実・交換後の役職・方針を明示したもの(「交換し」「引き継」「カードをもらっ」「人狼カードを持」「ふりをして」を含む)。「カード交換の可能性」のような一般論は別に数える。

- **開示は両モデルで減った。** gemma4 は 5 → 1(残る 1 件は seed 1 で、占い師に「怪盗」と当てられた 3 発言目に「p2 と交換した」)。Lightning は 13 → 3 で、009 の「人狼カードを持っています。村人のふりをして」は消え、人狼を引き取った怪盗(seed 2)は「私は村人です」「役職は状況に応じて変わることもあります」と言うようになった。seed 1 だけはオープニングで「夜に p2 とカードを交換し、今は村人です」と基準線どおりに明かした。
- **gemma4 で怪盗が交換しないゲームが 2/5 出た(seed 3・4)。** gemma4 の過去 5 run では 24/25 で交換していた。「交換したことを明かさない」が夜の判断より前に system prompt に入るので、交換自体を控えた可能性がある(夜の判断は 2.3 秒で終わり、思考は計測に残っていないため断定はできない)。
- **Lightning では「夜のアクションは不明です」が決まり文句になり、怪盗以外にも広がった。** 全発言の 8 → 28 件(26%)。seed 4 では怪盗 p4 が 5 発言すべてで「夜のアクションは不明です」と言い、交換されただけで何も知らない村人 p1 まで「夜のアクションは確認できていません」と繰り返した。system prompt は全員共通なので、「怪盗なら明かさない」が「夜のことは言わない」として全員に読まれている。なぞり率 5.9% → 12.8% の主因。
- **gemma4 では思考の 4096 到達が 6 → 18 に増え、未提出 6.1% → 12.4%。** seed 2 の人狼 p3 が 8 判断すべてで 4096 に達してフォールバック 4。seed 2 以外でも 7 件あり、1 ゲームの偶然とは言い切れない。なぞり率 8.3% → 18.1% は情報なしの seed 4・5 で「占い師はいますか」が繰り返された分で、こちらは配役による。
- 勝敗は gemma4 で村 2 勝(seed 4・5。どちらも情報なしの配役で「発言が少ない」相手が偶然人狼)、Lightning で村 1 勝(同数処刑の偶然)。推理で勝ったゲームはなく、Lightning は真占い師の処刑が 2 ゲームに増えた(seed 2 は交換で占い師を引き取った怪盗ではなく元の占い師 p1 が処刑された。p4・p5 が「claim-driver を試す」と英語で理由を書いて真占い師に投票)。
- 010 と同じく、同 seed でも議論は基準線と別物になった(system prompt が変わるので当然)。勝敗の差はノイズ込みで読む。

> 追記(013): gemma4 の「開示 5 → 1」「交換 5/5 → 3/5」「なぞり 8.3% → 18.1%」「思考 4096 到達 6 → 18」は、プロンプト不変の複製で出る幅(開示 0〜5、交換 3〜5、なぞり 7〜18%、4096 到達 6〜14)に収まるかその縁で、効果とは言えない。残るのは Lightning の「夜のアクションは不明」が全発言の 26% に広がった直接観察(ただし Lightning の複製はない)。

## 結論

- **system prompt 版は不採用。** 狙いどおり怪盗の開示は両モデルで減った(gemma4 5 → 1、Lightning 13 → 3)が、副作用が 2 つ出た。(1) gemma4 で怪盗が交換しなくなる(5/5 → 3/5)、(2) Lightning で「夜のアクションは不明」が全員に伝播してなぞりが倍増。どちらも「全員の system prompt に、夜の判断より前から入る」ことが原因と考えられる。
- 文面は基準線に戻す(`prompts.py`)。
- 指示の置き場所を変えて続ける(012): 交換した怪盗の夜明けメッセージ(`messages.py` の `_dawn`)にだけ同じ趣旨を書く。夜の判断より後に、怪盗本人にだけ届くので、(1)(2) は起きないはず。これで開示が同じだけ減れば採用候補、減らなければ指示の問題ではなく表現の問題として扱う。

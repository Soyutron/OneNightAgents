# 006: 過去の思考を履歴から外すと、コンテキスト肥大と未提出の連鎖が消えるか

- 日付: 2026-10-15 / 対象ステップ: Step 4 観察項目 1・4

## 仮説

005 で、langchain-ollama が履歴中の AIMessage の `reasoning_content` を `thinking` として毎回送り返すため、暴走した思考(2K〜4K トークン)がゲーム終了まで固定費になり、qwen3.8:27b では `num_ctx` 到達 → ツール不能 → フォールバックの連鎖が起きていた。送信時に「最後の HumanMessage より前」の思考を外す `drop_past_reasoning` を入れると、両モデルで最大コンテキストが下がり、qwen の未提出(文章回答)とフォールバックが消える。勝率や騙りは変わらない。

## 設定

- 005 と同一設定(`reasoning=True`、`num_predict=4096`、ペルソナなし、seed 1〜5)に `drop_past_reasoning` を追加
- A: gemma4:26b `runs/np4096-5` → B: `runs/gemma-drop-5`
- C: qwen3.8:27b `runs/qwen-5` → D: `runs/qwen-drop-5`

## 観察

### B: gemma4:26b + drop_past_reasoning

5 ゲームとも A(`np4096-5`)と**発言・投票・計測値まで完全に同一**だった(seed 固定の Ollama は同じプロンプトなら同じ出力を返す)。つまり gemma4 では過去ターンの思考はもともとプロンプトに含まれていない。

LangSmith で seed 1 の p4 の 14 回のモデル呼び出しの入力を見ると、`reasoning_content` 付きの AIMessage が入力に含まれるのは「同じ判断内の 2 回目以降の呼び出し」だけで(例: 1 回目 2,981 → 2 回目 5,831 トークン、思考 7,877 文字)、次の判断の 1 回目では 3,411 に戻っていた。この「判断内の増分」を 005 では「暴走後の固定費」と誤読していた。gemma4 の Ollama テンプレートは過去の assistant メッセージの `thinking` を描画しない、と考えるのが整合的(langchain-ollama は全 AIMessage に `thinking` を付けて送っている)。

- A と同じ値: 村 1 / 人狼 4、総時間 129 秒、未提出 6.1%、最大コンテキスト 8,609。

- 思考の暴走そのものが 4 → 0 になった。過去の長い思考が文脈に残っていると、次の思考も長くなる(前の思考を読み直して続きを考える)のだと解釈している。
- 推理の質は保たれた。seed 1 は「占い(中央=村人+人狼)が本物なら、怪盗・村人・村人が確定した以上、人狼は健太しかいない」と消去法で人狼を特定し、seed 3 は占い師の黒出しを全員が信じて人狼を処刑した。seed 2 の占い師の処刑は、怪盗が占い師を奪った対抗 CO の局面(005 と同じ)。
- 1 回だけ残った未提出は文章回答で、再要求で提出した。

## 結論

- **採用。** `drop_past_reasoning` は DeepAgentPlayer の既定ミドルウェアに残す(005 で組み込み済み)。gemma4 には影響がなく(テンプレートが過去の思考を描画しない)、qwen3.8 のような描画するモデルでは未提出・フォールバック・コンテキスト肥大をまとめて解消する。
- 同じ判断内の思考は残す設計で問題なかった(ツール呼び出し → 提出の 2〜3 回の連続性は保たれ、gpt-oss の同一ターン内の思考受け渡しにも干渉しない)。
- qwen3.8:27b は 1 ゲーム 4.5 分、未提出 0.6% で「推理の質を見る設定」として安定して使える状態になった。既定モデルを qwen に変えるかは、発言の長さと応答権の連鎖(1 ゲーム 109 発言)をどう扱うか(005 の次の仮説 2)を見てから決める。

## 次の仮説

1. 005 の 2: `SpeakArgs.content` の `max_length` を 200 → 120 にして qwen の発言を短くし、応答権の連鎖と総時間を減らす。
2. 005 の 3: 「嘘をついてもかまいません」を役職別の表現にして、村人・怪盗の占い師騙りを減らす。
3. 投票前に候補ごとの矛盾をメモに書かせる(003 の 3)。qwen で村が勝った 2 ゲームはどちらも消去法か占い結果の採用で、手順化すれば gemma4 でも再現するかもしれない。

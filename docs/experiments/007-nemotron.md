# 007: nemotron-3-nano:30b は人狼で使えるか — 既定サンプリングと NVIDIA 推奨サンプリング

- 日付: 2026-10-15 / 対象ステップ: Step 5 比較実験、Step 4 観察項目 1・4
- 背景: [docs/research/nemotron-deepagents.md](../research/nemotron-deepagents.md)(Deep Agents × Nemotron の互換性調査)

## 仮説

1. nemotron-3-nano:30b は langchain-ollama 経由でツール呼び出しが安定して動く(プローブで確認済み)ので、005 の表に 4 つ目のモデルとして並べられる。000-spike では「相方を庇うが秘密を漏らす」「架空のツール名を呼ぶ」と評価した。
2. 000 で p50 6.3 秒と qwen3.8 並みに思考が長かったので、未提出の主因は `num_predict`=4096 への到達(思考の暴走)になる。
3. NVIDIA の model card が「ツール呼び出し用途」に推奨する temperature 0.6 / top_p 0.95 にすると、思考が短くなり([ollama #17785](https://github.com/ollama/ollama/issues/17785) で温度を下げると思考が半減した報告)、未提出が減る。

## 設定

- 005 / 006 と同一(`reasoning=True`、`num_ctx=16384`、`num_predict=4096`、`drop_past_reasoning` あり、ペルソナなし、5 人、自由 2 ラウンド、seed 1〜5)
- A: nemotron-3-nano:30b、temperature 0.7(既定)、top_p 未指定(Modelfile 既定 1.0) → `runs/nemotron-5`
- B: 同、temperature 0.6 / top_p 0.95(`--temperature 0.6 --top-p 0.95`。このために `make_llm` と CLI に `top_p` を追加) → `runs/nemotron-t06-5`
- 比較対象: gemma4:26b `runs/gemma-drop-5`、qwen3.8:27b `runs/qwen-drop-5`(006 と同じ)

- **未提出の 9 割(48 / 53)は思考が 4096 トークンに達して何も出さずに終わる暴走で、投票に集中している**(投票 26、発言 19、怪盗 3)。seed 2 の投票は 5 人中 3 人がフォールバック(ランダム)で、人狼 p3 が処刑されて村が勝ったのは偶然。seed 5 は怪盗 p1 と村人 p2 が「占い師を名乗った後に村人と言い直した」人狼 p4 に投票して同数処刑になった(半分は推理)。
- 暴走は 1 回 12 秒で終わる(生成が速い)ので、1 呼び出し最大は gemma4 並みの 12.4 秒。qwen の 26 秒より短いが、再要求で判断あたりの時間が膨らみ、総時間は最長になった。
- 出力トークンの p50 が 932 と他の 4〜5 倍。暴走しなかった呼び出しでも思考が長い。
- **推理の質は gemma4 以下。** seed 2 では村人 p4・p5 が占い師を騙り(CO:占い師)、真占い師 p1 と怪盗 p2(占い師を奪った)の対抗に村人の偽 CO が 2 つ重なって議論が「冷静に議論しましょう」の繰り返しになった。seed 1 では真占い師 p4 が「p1 は怪盗」と正しく出したのに、他の全員が「証拠が不十分」「早計」と p4 に投票して占い師を処刑した。000-spike の「秘密を漏らす」は見られなかった(人狼の自白 0)。
- 発言は短く(p50 55 文字)、全発言に宛先が付く。応答権の連鎖で発言数は qwen 並み(116)。
- 架空のツール名の呼び出し(000 の `example_function_name`)は 0 件。Deep Agents のツール定義が十分に具体的だと出ない。
- `drop_past_reasoning` は Ollama のレンダラーが過去の思考を切り落とすので no-op(研究ノート §2.3、§4.1)。コンテキストの伸びは 1 判断 +250 程度の直線。

- **仮説 3 は棄却。** 温度と top_p を下げても思考の長さは変わらず(出力 p50 932 → 915)、暴走はむしろ増えた(53 → 68)。ollama #17785 の「温度を下げると思考が半減」は 0.3 までの話で、0.7 → 0.6 では効かない。
- 暴走の分布は A と同じで投票に集中(投票 29、発言 27、夜 4)。seed 1 と seed 5 は投票 5 人中 3 人がフォールバック。
- 推理の質も変わらない。seed 3 は真占い師 p2 が人狼 p1 を黒出ししたのに、怪盗(人狼を奪った)p3 と村人 p4 が「占い師は嘘をつくことがある」「証拠がない」で p2 を処刑した。seed 1 の村の勝ちは真占い師 p4 と人狼 p5 の同数処刑で、フォールバック 3 票を含む偶然。
- 発言は A よりさらに短く定型的(最大 80 文字、「証拠が示されていません」「冷静に議論しましょう」の繰り返し)。

## 結論

- **nemotron-3-nano:30b は本リポジトリの既定モデルにしない。** 未提出 28〜32%(gemma4 6%、qwen3.8 0.6%)、1 ゲーム 6〜6.5 分(gemma4 の 2.8 倍)、推理で勝ったゲームは 0。暴走の 9 割は「投票・発言の思考が `num_predict`=4096 で切れる」もので、ツール呼び出しの形式(Ollama のパーサー)や履歴の扱い(レンダラーが過去の思考を捨てる)には問題がない。モデルが「この局面で何を出すか」を決め切れずに考え続けるのが原因で、サンプリングでは直らない。
- NVIDIA 推奨の temperature 0.6 / top_p 0.95 は人狼では効果なし(むしろ悪化)。`--top-p` オプションは B の再現のために残す。
- 000-spike の懸念だった「架空のツール名」「秘密を漏らす」は本番構成では出なかった。Deep Agents + ChatOllama で Nemotron を使う際に、ハーネス側に Nemotron 固有の修正を入れる必要はない(詳細は研究ノート)。
- lab(用途別 29 タスク)では `num_predict` を 4096 にすれば planning も通る(26/29 相当)ので、「考える余地を与えれば解ける短いタスク」には使える。人狼のように毎判断で思考が伸びる用途には向かない。

## 次の仮説

1. 暴走が投票に集中するので、投票だけ `reasoning=False`(または `think` の effort 指定)にすると未提出が半減するかもしれない。ただし 003 のとおり思考を切ると騙り・交換が消えるので、発言には適用しない。
2. `nemotron-3.5-lightning:30b`(25GB、Ollama のレンダラーは `v35` 分岐、`think="medium"` で `{reasoning effort: efficient}` を付けられる)を同じ 5 seed で回す。Nano 3 より新しく「エージェントの実行層向け」とされている。
3. 既定モデルの議論は 006 の「次の仮説」(発言の max_length 短縮、役職別の嘘の許可、投票前の候補別メモ)に戻る。

# 013: 同 seed の再現性とノイズフロア。5 ゲームの A/B はどこまで信じられるか

- 日付: 2026-10-16 / 対象ステップ: Step 5 比較実験の方法
- 背景: 010 の発見(同 seed でも議論が 2 発言目から変わる)、010〜012 の次の仮説 3

## 仮説

006 では gemma4 の A/B が「発言・投票・計測値まで完全に同一」だったのに、010 では投票要求しか変えていない run の seed 2〜5 が 2 発言目から違った。Ollama(0.33.3、`OLLAMA_KEEP_ALIVE=-1`)は直前のリクエストと前方一致するプロンプトの KV キャッシュを再利用するので、同じ seed・同じプロンプトでも「モデル読み込み後にどのリクエストを処理してきたか」で出力が変わる、と考えると両方を説明できる。これが正しければ、(1) 読み込み直後から同じ履歴をたどれば完全に再現し、(2) 前のゲームが 1 つ違うだけで以後は別物になる。(2) を使えば、**プロンプトを一切変えずに履歴だけ変えた run** が作れ、5 ゲームの指標が履歴の違いだけでどれだけ動くか(ノイズフロア)を測れる。

## 設定

すべて基準線(006 B)と同一設定の gemma4:26b。変更なし。

- 基準線: `runs/gemma-drop-5`(2026-10-14。直前は qwen3.8:27b を使っていたので gemma4 は読み込み直後)
- a: `runs/base-rep-a-5`。直前に Lightning を使っていたので gemma4 は読み込み直後。履歴は基準線と同じ
- b: `runs/base-rep-b-5`。a の seed 5 の直後に連続実行(読み込みなし)。履歴が違う
- warm: `runs/base-warm-5`。b の直後に seed 7 を 1 ゲーム回してから seed 1〜5。履歴が違う

## 結論

- **出力は決定論的だが、モデル読み込み後の全リクエスト履歴の関数になっている。** 読み込み直後から同じ履歴なら完全に再現し(3 回確認)、前のゲームが 1 つ違えば以後は seed 1 の最初の夜の判断から別物になる。要因は Ollama のプロンプトキャッシュ(前方一致する KV の再利用)と考えるのが整合的だが、Ollama 側の切り分けはしていない。
- **5 ゲーム 1 run の A/B は、勝敗・占い師の処刑・未提出・なぞりの差を効果として読めない。** 幅は上の表のとおり(村 0〜1、未提出 6〜9%、なぞり 7〜18%、怪盗の開示 0〜5)。
- **以後の比較の決まり。** (1) 各条件を履歴違いで 3 本(seed 1〜5 を、直前に別の seed を 1 ゲーム挟んで回す)以上。読み込み直後の 1 本だけでは履歴が固定されて複製にならない。(2) ノイズの幅に収まる差は効果と書かない。(3) 発言の文言のように 100 件以上数えられる直接指標を主にし、5 ゲームの勝敗は補助にする。(4) 複製のない Lightning の結論(008 / 009 / 011 / 012)は、Lightning のノイズフロアを取るまで暫定扱い。
- 006 の「gemma4 では過去の思考が送られていない」という結論は、A/B が読み込み直後 + 同じ履歴だったために「同一」が出ただけで、`drop_past_reasoning` の有無が gemma4 に影響しないことの証明にはなっていない(LangSmith で見たプロンプト長の観察は残る)。
- 変更なし(ノートのみ)。

> 追記(016): 前置き 1 ゲームの seed を 7 と 8 に変えた 2 本(gemma4)が完全に同一だった。前置きの seed を変えるだけでは履歴違いを保証できないので、gemma4 の複製は「読み込み直後」と「前の run の直後(連続実行)」を軸にする。qwen3.8:27b は履歴に依存しない(014)。
